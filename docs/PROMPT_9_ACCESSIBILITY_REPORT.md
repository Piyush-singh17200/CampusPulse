# Prompt 9 — Accessibility Report

**Project:** CampusPulse
**Date:** 18 November 2026
**Target:** WCAG 2.2 Level AA intent
**Status:** Automated keyboard and responsive checks passed; manual assistive-
technology review remains outstanding

This report describes the accessibility changes made in Prompt 9 and the checks
that were actually run. It is not a WCAG conformance certification.

## 1. Scope

The review covered:

- Public landing page.
- Login, registration, forgot-password, and reset-password pages.
- Account page.
- Student, club, college, and platform dashboards.
- Keyboard-only navigation and skip navigation.
- Form labels on the authentication flow.
- Responsive layout at 375, 768, and 1440 px.
- Focus visibility and reduced-motion handling already present in the design
  system.

It did not include a full screen-reader audit, a contrast measurement of every
color pair, or a third-party accessibility audit.

## 2. Changes

### Skip navigation

A reusable `src/components/ui/skip-link.tsx` component was added:

```tsx
<a
  href={`#${targetId}`}
  className="sr-only focus:not-sr-only focus:absolute focus:left-4 focus:top-4 focus:z-[100] ..."
>
  Skip to content
</a>
```

The link is visually hidden until it receives keyboard focus, so it does not
change the visual design. It is the first focusable element on the page.

Applied to:

| Layout                | Target                                                    |
| --------------------- | --------------------------------------------------------- |
| Landing page          | `#main-content` (existing link, now a focusable target)   |
| Dashboard shell       | `#dashboard-main` (existing link, now a focusable target) |
| Authentication layout | `#main-content` (new link)                                |
| Account layout        | `#main-content` (new link)                                |

Each target has `tabIndex={-1}` and `focus:outline-none`. Without the tab index,
an in-page link scrolls but does not move keyboard focus; with it, `Enter` on
the skip link moves focus into the main landmark.

### Account page copy

The account page previously linked to a stale destination. It now uses
`dashboardPathForRole(user.role)` so the “Go to dashboard” action lands on the
correct dashboard for the signed-in role.

### Existing accessible patterns retained

- Visible `focus-visible` outlines on navigation and controls.
- `aria-current="page"` on the active dashboard navigation item.
- `aria-live="polite"` regions for form and scan status messages.
- Screen-reader-only labels for icon-only controls and correction reasons.
- A screen-reader-only table alternative for chart-like data.
- `prefers-reduced-motion: reduce` rules in `src/app/globals.css`.
- Semantic landmarks (`header`, `nav`, `main`, `footer`) in the shells.

## 3. Automated browser checks

`tests/e2e/prompt-9.spec.ts` includes a keyboard and responsive test.

### Keyboard

On `/login` at 375 × 812:

1. Press `Tab`.
2. The focused element is the skip link with text **“Skip to content”**.
3. Press `Enter`.
4. The URL ends with `#main-content`.
5. `document.activeElement.id` becomes `main-content`.

On `/student`, the test asserts:

- `main#dashboard-main` is visible.
- It has `tabindex="-1"`.
- The page has exactly one `h1`.

### Labels

The login test asserts:

- The email input is reachable by its label **“Email address”**.
- The password input is visible.
- The password input's accessible name is **“Password”**.
- A `<label for="password">` element contains “Password”.

The required-field asterisk is marked `aria-hidden="true"`, so it does not
pollute the accessible name.

### Responsive layout

At 375, 768, and 1440 px, the test asserts:

```text
document.documentElement.scrollWidth - window.innerWidth <= 1
```

This catches horizontal overflow, a common mobile accessibility failure. The
login page is also checked at 375 px.

## 5. Manual checks still required

These were not performed and must not be reported as verified:

| Check                          | Why it matters                                                 | Suggested method                                                                                                                |
| ------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Screen-reader walkthrough      | Confirms reading order, names, roles, and live-region behavior | NVDA + Firefox/Chrome on Windows, or VoiceOver + Safari on macOS                                                                |
| Color contrast measurement     | The design uses muted text and soft backgrounds                | Measure all text/background pairs with axe DevTools or a contrast analyzer; target 4.5:1 for normal text and 3:1 for large text |
| 200% browser zoom              | Reflow and clipping can differ from a 375 px viewport          | Test login, dashboards, tables, and dialogs at 200% zoom                                                                        |
| Keyboard-only task completion  | The automated test covers the skip link, not every workflow    | Create an event, register, scan attendance, export, and moderate feedback using only the keyboard                               |
| Focus trap in dialogs          | Modal dialogs must contain focus and restore it on close       | Test any dialog/drawer used by the dashboard                                                                                    |
| Form error announcement        | Errors must be announced and associated with fields            | Submit invalid forms with a screen reader                                                                                       |
| Reduced-motion preference      | Motion should be suppressed                                    | Enable the OS reduced-motion setting and check transitions                                                                      |
| PDF/CSV download announcements | Downloads may not be announced consistently                    | Test with a screen reader and browser download settings                                                                         |

## 6. Design-system observations

- The design intentionally uses small uppercase labels and muted text in
  several places. These are candidates for contrast measurement, especially on
  `paper-dim` and `canvas` backgrounds.
- Dashboard tables are responsive and use horizontal scrolling containers on
  small screens. The overflow test passed, but a screen-reader user should still
  be able to associate headers with cells; the existing table markup uses
  semantic `th`/`td` elements.
- The skip link uses `position: absolute` in the auth/account layouts and
  `position: fixed` in the dashboard shell. Both were visually verified through
  the focus test; a manual check should confirm the link is not clipped by a
  transformed ancestor.
